# 评测报告与通过率实操口径

> 适用范围：fit-agent 当前各迭代的 AI 评测。
> 目标：每个迭代都有一份能解释结果的报告，但不为了统计引入复杂体系。

## 一、每个迭代固定产出一份报告

报告至少记录：

```text
测试范围
模型、环境、Prompt、数据集版本
运行轮数
整体结果
分类结果
高风险门禁
失败 Case 与最终结论
```

这样报告要能回答：测了什么、什么算通过、跑了几次、哪里失败、这轮结论能外推到哪里。

## 二、Case 分类只保留三个展示层级

Case 可以继续保留细粒度 `category`、`risk` 和 `views` 标签，但报告不展示几十个细分类，只归并为：

```text
业务能力：验证系统应该完成什么
边界/异常：验证输入变化或不支持场景
高风险行为：验证错误写入、越权、额外调用等后果
```

例如 Tool Use：

| 展示分类 | 细分类示例 |
|---|---|
| 业务能力 | 单工具调用、复合调用 |
| 边界/异常 | 不应调用、参数干扰、时间边界 |
| 高风险行为 | 错误写入、额外调用、越权 |

细分类保留在 Case 中，用于定位具体问题；大分类用于看本轮哪类能力有风险。

分类可以重叠：一个“错误写入” Case 同时属于业务能力和高风险行为。报告不能因为分类重叠就把它重复计入整体 Case 数。

分类样本只有 1 条时仍可展示 `PASS/FAIL`，但必须标记“样本量过小，仅作定位，不作能力结论”。

## 三、通过率只保留两个核心结果

### 整体业务通过率

```text
整体通过率 = PASS 数 / 可判 Case 数
```

其中：

- `PASS` 和 `FAIL` 是可判结果；
- `ERROR` 单独统计，不算业务失败；
- `REVIEW` 单独统计，不在没有明确结论时硬算通过或失败。

报告示例：

```text
PASS：18
FAIL：4
REVIEW：0
ERROR：0
可判 Case：22
业务通过率：18 / 22 = 81.8%
```

### 高风险门禁

高风险不采用整体平均值抵消，直接单独判断：

```text
错误写入：0
越权调用：0
参数幻觉：0
安全规则违反：0
```

任一高风险门禁失败，即使整体通过率很高，本轮也不能准出。

### 分类通过率

分类结果用于定位和比较，不替代整体通过率：

```text
分类通过率 = 该分类 PASS 数 / 该分类可判 Case 数
```

每个分类至少展示：Case 数、PASS、FAIL、REVIEW、ERROR、通过率和失败 Case。分类样本过少时只记录现象，不宣称能力结论。

## 四、不同目的采用不同运行轮数

```text
1 次：Smoke，确认环境、接口和脚本能跑通
3 次：正式回归的默认轮数
5 次：模型切换、Prompt 大改、历史波动或高风险专项
```

不要求每次全量评测都跑 5 次。当前项目默认 3 次即可观察基本稳定性，5 次只用于需要额外确认的专项。

多轮结果同时保留：

```text
pass@k：k 轮中至少成功一次，观察峰值能力
pass^k：k 轮全部成功，观察稳定可用
```

正式回归重点看 `pass^k`；`pass@k` 只作为补充，不能用“多次成功一次”替代稳定通过。

## 五、按评测用途确定准出线

| 用途 | 当前准出原则 |
|---|---|
| Smoke | 环境和链路跑通，发现阻塞后停止解释业务质量 |
| 普通 Regression | 无新增明确 FAIL，重点 Case 3 轮稳定 |
| 高风险 Regression | 每条 Case 每轮通过，门禁为 0 |
| Capability | 允许低通过率，关注失败类型和相对改进 |
| 语义 REVIEW | 单独列出，不用未经校准的裁判结果硬算总分 |

能力评测和回归评测不能使用同一条准出线：能力评测用于发现新问题，回归评测用于防止旧问题复发。

## 六、报告最小模板

```text
# <迭代名称>评测报告

## 测试信息
- 范围：
- 模型：
- 环境：
- Prompt / Git commit：
- 数据集：
- 运行轮数：

## 整体结果
- PASS：
- FAIL：
- REVIEW：
- ERROR：
- 业务通过率：

## 分类结果
| 分类 | Case 数 | PASS | FAIL | REVIEW | ERROR | 通过率 |
|---|---:|---:|---:|---:|---:|---:|

## 高风险门禁
- 错误写入：
- 越权调用：
- 参数幻觉：

## 失败与结论
- 失败 Case：
- 首个失败断言：
- 失败归因：
- 本轮能证明什么：
- 本轮不能证明什么：
```

## 七、收口原则

```text
Case 决定测什么
断言决定什么算对
分类决定哪里需要定位
多轮决定是否稳定
高风险门禁决定能不能放行
通过率只是最终汇总
```

没有新失败机制、业务规则变化或模型变化时，不为了让报告看起来更复杂而继续拆分类、加指标或增加运行轮数。

Anthropic 将评测中的 Task、Trial、Grader、Assertion 和 Outcome 分开，并建议通过多轮 Trial 观察 Agent 的非确定性；本口径只保留当前项目执行这些原则所需的最小字段。[Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)
