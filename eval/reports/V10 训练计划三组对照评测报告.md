## 3. 三组对照（第 1 轮）

| 指标 | v7 | llm_only | v2（修复前） |
|---|---|---|---|
| PASS / FAIL | 0 / 15 | 0 / 15 | 14 / 1 |
| 违反计数 | D1 14、D4 2、R5 2、R4 1 | R1 104、R5 2、R6 2 | 未交付 1（pv-06，重生成后仍 D1） |
| 计划交付 | 11/11 | 11/11 | 10/11 |
| 时长达标 | 0/11 | 0/11（无法核算） | 10/11 |
| 首次即通过 | 0/15 | 0/15 | 7/15 |
| 平均 token | 941 | 713 | 6503 |

**关于 llm_only 的 R1 = 104，需要如实解读**：它表示「动作名称对不上核验过的动作库」，**不等于模型编造动作**。未匹配的名称里有一部分是库内动作的同义说法（如「手臂环绕」对「手臂绕环」、「登山者」对「登山跑」、「哑铃俯身划船」对「俯身哑铃划船」），一部分是库外的真实动作（如「靠墙静蹲」「引体向上」「哑铃飞鸟」）。它们的问题是**无法核验**：部位、器械、难度、单次耗时都没有依据，时长也就无法由代码核算。llm_only 真正越界的是 R5 与 R6 共 4 条，这类错误在真实产品里风险更高。

## 4. v2 修复（V10.4）

修复前 v2 的主要问题：11 条出计划的 Case 里只有 3 条首次通过，8 条首次因 D1 被退回（模型普遍低估时长约 20%），重生成后仍有 1 条不达标；另外「在健身房练翘臀」没有用任何健身房器械。

| 问题 | 改法 | 未选方案 |
|---|---|---|
| 首次 D1 不达标 | 代码时长微调：动作与结构合格、只差时长时，在 D2 范围内贪心调整主训练的轮数、组数与休息；调不进区间再重生成 | 只改 Prompt 让模型算得更准：时长属于「数据要对」层，应由代码保证，模型算术不稳定 |
| 有器械却不用 | `plan_compose` 升 v2：新增指引「有器械时主训练优先用器械」，只作参考不硬拦 | 设为红线：是否用器械是编排取舍，不是安全问题 |

两项改动分别用不同指标衡量（首次通过与微调次数、器械使用），可以各自归因。

| 指标 | 修复前（1 轮） | 修复后（3 轮合计） |
|---|---|---|
| PASS | 14/15 | **45/45** |
| 首次即通过 | 7/15 | **45/45** |
| 由代码微调时长 | - | 23/33 份计划 |
| 有器械时主训练用上器械 | - | 18/18 |
| 平均 token | 6503 | **约 3740（−43%）** |

健身房三条的主训练中健身房档动作数：pv-03 5→6、pv-07 3→3、pv-11 0→1。
