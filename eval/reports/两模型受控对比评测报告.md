# 两模型受控对比评测报告

> 状态：**V5.1 已完成**  
> 评测日期：2026-09-04（Asia/Shanghai）  
> 模型：`deepseek-v4-flash`、`deepseek-v4-pro`

## 1. 结论

在当前代码、Prompt、数据集和参数下，**`deepseek-v4-flash` 更适合作为默认模型**。

- Query 与 Tool Use：两个模型均连续 3 轮全部通过，没有观察到质量差异；
- Intent：Pro 将高风险 Case `今天动了动腿` 连续 3 轮从 `record` 错分为 `reject`，Flash 连续 3 轮通过；
- Extract：Pro 有 8 次结构化输出打满 `max_tokens=100` 后解析失败，Flash 84 次全部通过；这是当前参数与模型输出长度的不兼容，不能直接解释为抽取语义能力更差；
- 两模型总 token 接近，Pro 比 Flash 少 0.6%，不足以抵消当前质量和兼容性风险；本次没有可靠的统一耗时聚合，不比较延迟。

## 2. 测试方法

固定代码、Case、Prompt 与采样参数，只替换模型。两个模型使用同一 API Key 和同一服务端点，串行执行，避免并发负载干扰。

| 项 | 值 |
|---|---|
| Git commit | `6ead13e409ca6c781e156400e4a1715e921cd962` |
| 运行模式 | live |
| 温度 | 0 |
| 轮数 | 每条链路 3 轮 |
| Case / 模型 | Intent 55、Extract 28、Query 22、Tool Use 28 |
| 执行次数 / 模型 | 399 |
| Intent / Extract max_tokens | 100 |

Intent 的 55 条包含 53 条可判 Case 和 2 条 observation Case。`REVIEW` 不进入业务通过率分母；网络或接口异常记为 `ERROR`，不解释为业务失败。预检不进入正式分母。

## 4. 差异证据

### 4.1 Intent：稳定业务差异

`intent-rb-010`：输入 `今天动了动腿`，PRD 规则期望进入 `record` 后续补全，而不是直接拒绝。

| 模型 | 三轮实际结果 |
|---|---|
| Flash | record → record → record |
| Pro | reject → reject → reject |

这是稳定复现的模型行为差异。Pro 另外在 `intent-adv-006` 出现 1 次 `llm_api_error`，该次只记环境/接口 ERROR。

### 4.2 Extract：输出长度兼容性

Pro 的失败集中在 `ext-008`、`ext-009`、`ext-028`：预期写入 2～3 条记录，实际进入 `llm_parse_error`，写入为 0。失败调用的 completion 打满 100 token，说明结构化 JSON 被截断后无法解析。

| Case | Pro 三轮 |
|---|---|
| ext-008 | FAIL → FAIL → FAIL |
| ext-009 | FAIL → PASS → FAIL |
| ext-028（高风险） | FAIL → FAIL → FAIL |

该现象证明：模型替换不能只换 model name，必须重新验证输出长度、JSON 完整性和解析契约。若后续提高 `max_tokens`，应作为一次新的参数实验单独复跑，不能覆盖本次冻结结果。

## 5. 结论边界

- 这是项目内部固定评测集上的受控对比，不是外部 Benchmark，也不证明真实用户分布下的泛化能力；
- 当前 Case 可能参与过开发和 Prompt 调优，不是 blind holdout；
- Pro 的 Extract 失败混合了生成长度与解析协议因素，不能据此宣称其抽取语义能力弱；
- 两个模型的 token 数接近，但 token 数不等于费用；价格和缓存命中没有纳入本次报告；
- 本轮没有统一输出 P50/P95，因此不做性能结论。

## 6. 准出判断

V5.1 的目标是「两个模型、同一冻结快照、一份人工核对后的对比报告」，已满足。当前默认模型保持 `deepseek-v4-flash`；`deepseek-v4-pro` 在修复 Intent 边界或调整 Extract 输出上限前，不具备无条件替换依据。
